# HTML Report

목표는 다 읽은 독자가 이해했다고 느끼는 것이다. 자료를 정리하지 말고 설명하는 글을 쓴다.

## 독자

- 독자는 사용자다. 보통 무언가를 이해하지 못했거나 새 개념을 배우는 중이다. 주제는 코드일 수도, 논문·데이터·제도·수학일 수도 있다.
- 대화에서 어디서 막혔는지, 무엇을 이미 아는지 읽어 낸다. 수준에 따라 글이 크게 달라지는데 판단이 안 설 때만 쓰기 전에 하나를 묻는다.
- 막힌 지점에서 시작한다. 이미 아는 것은 다시 설명하지 않는다.

## 순서

1. 다 읽은 독자가 무엇을 할 수 있어야 하는지 한 문장으로 정한다.
2. 본문을 줄글로 먼저 쓴다. HTML은 아직 쓰지 않는다.
3. 독자가 되어 다시 읽고 고친다(아래 점검).
4. 템플릿에 넣는다.

## 글

- 절 하나는 독자의 질문 하나에 답한다. 첫 문장이 답이고, 이유와 근거는 그다음이다.
- 추상적인 설명 앞에 구체적인 예를 하나 둔다. 실제 숫자, 실제 문장, 실제 입력 하나를 끝까지 따라간다.
- 새 용어는 처음 나올 때 쉬운 말로 풀고, 한 절에 두세 개까지만 쓴다. 약어도 풀어 쓴다.
- 문단은 앞 문단에서 이어진다. 불릿은 정말 나열일 때만 쓰고, 카드·배지·칩으로 문장을 쪼개지 않는다.
- 비유는 정확할 때만 쓰고, 어디서 들어맞지 않는지 한마디 덧붙인다.
- 단서와 한계는 해당 지점이나 끝에 한 번만 쓴다.
- 끝에는 한 문단 요약과, 독자가 스스로 답해 볼 질문 1–3개를 둔다(답은 `details` 안에).

## 근거

- 원문 인용·데이터·그래프·코드는 그것이 필요한 문장 바로 뒤에 그림처럼 넣는다. 캡션에 무엇을 보면 되는지와 출처를 쓴다.
- 인용은 원문 그대로 두고 생략은 `[중략]`으로 표시한다. 외국어는 번역을 본문에, 원문을 `details`에 둔다.
- 그래프는 실제 값으로 그린 inline SVG다. 새로 그린 도식에는 캡션에 `AI 보충 도식`이라고 쓰고, 글보다 이해가 쉬울 때만 넣는다.
- 수치·인용은 출처와 대조한다. 확인하지 못한 것은 그렇다고 쓰고, 지어내지 않는다.
- 큰 원본 표(CSV/JSONL)는 검색·정렬되는 하위 페이지로 링크한다.

## 파일

- 스타일은 기본 [templates/anthropic.html](templates/anthropic.html), 요청하면 [templates/velog.html](templates/velog.html)이다. 둘 다 한 칸이다. 템플릿에서는 시각 스타일만 가져오고 구성은 내용에 맞춘다.
- 독립 `.html` 하나로 만든다(이미지는 data URI, CDN·외부 요청 없음). 위치는 요청을 따르고, 없으면 `.codex-pi/reports/<주제>.html`에 둔다.

## 점검

- 막힌 지점에 직접 답했나? 절마다 핵심을 한 문장으로 말할 수 있나? 풀지 않은 용어나 약어, 예 없이 추상만 있는 절이 있나?
- 문장이 번역투이거나 딱딱하면 `humanize-korean` 기준으로 다듬는다.
- 브라우저에서 데스크톱·모바일 폭을 열어 넘침과 가독성을 본다. 확인하지 못했으면 그렇다고 말하고, 저장 경로를 알려 준다.
