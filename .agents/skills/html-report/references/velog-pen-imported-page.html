원래 기록과 선택한 위치를 읽으면, 다음 질문을 앞선 맥락에 이어 붙일 수 있습니다.
AI 보충 시연 · 실제 Pi·Pen 화면을 촬영한 것이 아니라, 전달되는 정보를 설명한 모형입니다.
두 가지가 함께 있어야 합니다
기록은 “무슨 이야기를 했는가”입니다
질문과 답변, 도구 실행 결과가 여기에 해당합니다. 요약만 전달하면 세부 표현이나 앞에서 확인한 조건이 빠질 수 있습니다. 이번 방식은 요약문을 새로 만드는 대신 원래 기록을 사본에 담습니다.
위치는 “어디에서 계속할 것인가”입니다
같은 질문에서 두 가지 답을 시도했다면 대화에 갈림길이 생깁니다. 기록 전체를 갖고 있어도 현재 갈래를 모르면 다른 이야기로 이어질 수 있습니다. 그래서 선택된 마지막 항목, 즉 leaf도 함께 남깁니다.
책에 비유하면
대화 기록은 책의 내용이고, 선택한 위치는 책갈피입니다. 책을 옮기면서 책갈피도 그대로 꽂아두는 셈입니다.
실제 구현에서는 이렇게 남깁니다
코드 원문pi-handoff.cjs · exportHandoff의 일부
const entries = manager.getEntries();
const leaf = manager.getLeafId();
아래는 같은 함수에서 사본을 구성하는 부분입니다. 두 코드 사이의 검증·시간 생성 코드는 생략했습니다.
const snapshot = [
  { ...header, id: randomUUID(), timestamp, parentSession: source },
  ...entries,
  { type: 'custom', id: randomUUID(), parentId: leaf || null, timestamp,
    customType: 'pen-handoff', data: { source, leafId: leaf } },
].map(entry => JSON.stringify(entry)).join('\n') + '\n';
entries에 전체 기록을 담고, 새 항목의 parentId를 선택한 leaf에 연결합니다. 따라서 다른 갈래의 기록을 버리지 않으면서도 어느 위치에서 다시 시작할지 표시할 수 있습니다.
같은 대화를 잇지만, 같은 파일을 쓰지는 않습니다
그대로 가져오는 것
새롭게 달라지는 것
이전 질문·답변·도구 기록
이후 대화를 저장할 사본
선택한 분기와 이어갈 위치
새 화면에서 사용할 도구
원본은 보존하고 이후 대화는 Pen 사본에 기록합니다. 두 화면이 같은 파일에 동시에 쓰는 충돌을 피하려는 선택입니다. 실행 중인 작업 자체를 옮기는 기능은 아닙니다.
핵심은 “새 창 열기”가 아니라,
원래 기록 + 이어갈 위치를 함께 전달하는 것입니다.
